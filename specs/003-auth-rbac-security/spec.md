# Feature Specification: 用户鉴权、数据隔离与安全验证 (Auth & RBAC & Security)

**Feature Branch**: `003-auth-rbac-security`
**Created**: 2025-12-16
**Status**: Draft
**Input**: 功能迭代：用户鉴权、数据隔离与安全验证 - 实现登录验证码、角色权限控制和数据隔离
**Constitution**: v2.0.0 (Reference: `.specify/memory/constitution.md`)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 安全登录验证 (Priority: P1)

作为一个用户，我希望在登录时通过滑块验证码证明我不是机器人，以保护我的账户免受自动化攻击。

**Why this priority**: 登录安全是整个系统安全的基础，必须首先实现验证码机制来防止暴力破解攻击。

**Independent Test**: 可以通过尝试登录流程并完成滑块验证来独立测试，成功完成验证后才能提交登录请求。

**Acceptance Scenarios**:

1. **Given** 用户在登录页面, **When** 页面加载完成, **Then** 显示滑块验证码组件
2. **Given** 用户正在进行滑块验证, **When** 用户将滑块拖动到正确位置, **Then** 验证通过，登录按钮变为可用状态
3. **Given** 用户未完成滑块验证, **When** 用户点击登录按钮, **Then** 登录按钮保持禁用状态或提示完成验证
4. **Given** 用户滑块验证失败, **When** 验证失败3次, **Then** 刷新验证码图片，允许重新验证

---

### User Story 2 - 管理员全局数据访问 (Priority: P2)

作为一个管理员，我希望能够查看和管理系统中所有用户的爬虫任务和抓取数据，以便进行系统监控和问题排查。

**Why this priority**: 管理员需要"上帝视角"来监控系统运行状态，这是运维和管理的核心需求。

**Independent Test**: 可以通过管理员账户登录后访问任务列表，验证能看到所有用户的数据。

**Acceptance Scenarios**:

1. **Given** 管理员已登录系统, **When** 访问爬虫任务列表, **Then** 显示系统中所有用户创建的任务
2. **Given** 管理员已登录系统, **When** 访问抓取数据列表, **Then** 显示系统中所有用户抓取的新闻数据
3. **Given** 管理员已登录系统, **When** 查看任务详情, **Then** 能看到任务的创建者信息
4. **Given** 管理员已登录系统, **When** 需要修改某用户的任务, **Then** 拥有完整的编辑和删除权限

---

### User Story 3 - 普通用户数据隔离 (Priority: P2)

作为一个普通用户，我希望只能看到和操作自己创建的爬虫任务和数据，以保护我的数据隐私。

**Why this priority**: 数据隔离是多租户系统的核心安全要求，与管理员权限同等重要。

**Independent Test**: 可以通过两个普通用户账户分别创建任务，验证彼此无法看到对方的数据。

**Acceptance Scenarios**:

1. **Given** 普通用户已登录系统, **When** 访问爬虫任务列表, **Then** 仅显示该用户自己创建的任务
2. **Given** 普通用户已登录系统, **When** 访问抓取数据列表, **Then** 仅显示该用户自己抓取的数据
3. **Given** 普通用户已登录系统, **When** 尝试通过 URL 直接访问他人任务, **Then** 返回权限拒绝错误
4. **Given** 普通用户已登录系统, **When** 创建新任务, **Then** 任务自动关联到该用户

---

### User Story 4 - 历史数据迁移归属 (Priority: P3)

作为系统管理员，我希望现有的历史数据能够自动归属到默认管理员账户，以确保数据迁移的平滑过渡。

**Why this priority**: 这是数据迁移的技术需求，优先级低于核心功能但必须实现。

**Independent Test**: 可以通过检查数据库迁移后历史记录的 user_id 字段值来验证。

**Acceptance Scenarios**:

1. **Given** 系统存在历史数据, **When** 执行数据库迁移, **Then** 所有历史数据的 user_id 字段设置为管理员 ID (默认为 1)
2. **Given** 迁移完成后, **When** 管理员登录系统, **Then** 能看到所有历史数据

---

### Edge Cases

- 当用户网络不稳定导致滑块验证图片加载失败时，应显示重试按钮
- 当验证码 Token 过期时（超过有效期），应提示用户刷新验证码
- 当普通用户被提升为管理员角色后，应立即获得全局数据访问权限
- 当管理员被降级为普通用户后，应立即失去查看他人数据的权限
- 当用户账户被删除时，其关联数据的处理策略（保留或级联删除）

## Requirements *(mandatory)*

### Functional Requirements

**验证码机制**
- **FR-001**: 系统必须提供滑块拼图验证码功能，包含底图和缺口图
- **FR-002**: 系统必须提供获取验证码图片的接口，返回 Base64 编码的图片和加密验证 Token
- **FR-003**: 系统必须在登录请求中验证滑块位置的正确性，允许一定的容差范围
- **FR-004**: 验证失败时系统必须拒绝登录请求并返回明确的错误信息
- **FR-005**: 验证码组件必须适配 Glassmorphism (毛玻璃) UI 风格

**用户角色**
- **FR-006**: 系统必须支持两种用户角色：Admin（管理员）和 User（普通用户）
- **FR-007**: 管理员角色必须能够查看和管理系统中所有用户的数据
- **FR-008**: 普通用户角色必须只能查看和操作自己创建的数据

**数据隔离**
- **FR-009**: 所有核心业务数据表（爬虫任务、爬虫规则、新闻数据、社交会话）必须包含用户归属标识
- **FR-010**: 系统必须在数据查询层统一实现权限过滤逻辑
- **FR-011**: 管理员查询时返回所有数据，普通用户查询时自动过滤为仅本人数据
- **FR-012**: 创建新数据时必须自动关联当前登录用户

**数据迁移**
- **FR-013**: 系统必须提供数据库迁移机制，为现有表添加用户归属字段
- **FR-014**: 历史数据必须默认归属到 ID 为 1 的管理员账户

**安全性**
- **FR-015**: 验证码 Token 必须有时效限制
- **FR-016**: 系统必须记录登录验证失败的尝试次数和时间

### Key Entities

- **User**: 系统用户，包含角色属性（Admin/User），是所有业务数据的归属主体
- **CrawlerTask**: 爬虫任务，关联创建者用户
- **CrawlerRule**: 爬虫规则，关联创建者用户
- **NewsData**: 抓取的新闻数据，关联抓取任务的所属用户
- **SocialSession**: 社交媒体会话，关联创建者用户
- **CaptchaChallenge**: 验证码挑战，包含底图、缺口位置、加密 Token、过期时间

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能在 5 秒内完成滑块验证码验证流程
- **SC-002**: 验证码机制能有效阻止自动化登录尝试，人机验证通过率达到 95% 以上
- **SC-003**: 普通用户在任何情况下都无法访问其他用户的数据（100% 数据隔离）
- **SC-004**: 管理员能够在单一界面查看所有用户的任务和数据
- **SC-005**: 数据库迁移完成后，所有历史数据正确归属到管理员账户
- **SC-006**: 验证码组件与现有 UI 风格保持视觉一致性
- **SC-007**: 系统在 1000 个并发用户同时进行验证码验证时保持正常响应

## Assumptions

- 系统已有基础的用户登录功能，本迭代是在此基础上增强
- 用户表已存在，只需添加角色字段
- ID 为 1 的用户账户存在且为管理员角色
- 前端使用 React 框架，支持自定义组件开发
- 后端使用 FastAPI 框架，支持中间件和依赖注入
- 验证码容差范围默认设置为 ±5 像素
- 验证码 Token 有效期默认为 5 分钟
